### 已做的一处复位（我们引入的唯一偏差）
包里 `3ds/dspfirm.cdc` 原本被我换成 49,756 B 的 DSP1 固件 dump
（来自 D 盘模拟器的 sdmc，不是你这台 3DS 导出的）。本地校验它是**合法固件**：
`DSP1` magic @0x100、magic 后声明大小 49756、section header 结构完整 ——
不是坏文件。但 **DSP 固件随区域 / 系统版本变化**，别台机器的固件在本机
DSP 初始化阶段可能异常（homebrew「卡在声音初始化」是常见故障）。

因此已把默认改回**官方 Release 的 105 B 占位文本**：
作者 README 明确写真机上占位文件只是「没有声音」，不会崩。
那个合法 dump 移到 `optional/dspfirm.cdc.from-other-console` 留档。

→ **请重新拷一次 `3ds/dspfirm.cdc`（或直接把 SD 卡上这个文件删掉）再试。**
   要声音：在你这台机器上跑 DSP1（FBI → titleDB → DSP1），
   它会把本机固件导到 `sdmc:/3ds/dspfirm.cdc`，再覆盖即可。

现在 `real-hardware/3ds/` 与官方 Release 的 sdmc 结构**完全一致**
（只多了 `game.wbfs` 和空的 `nand/`），是最干净的对照配置。

### 按优先级排查（3dsx 也崩的情况）
0. **机型 —— 最关键**：项目 README 原话 "The original 3DS and 2DS can't
   run it." 必须是 **New 3DS / New 3DS XL / New 2DS XL**。老机器 268MHz 双核、
   可用内存 64MB、无 Core2，而程序要 `C3D_Init(1MB)`、假设 804MHz、并把渲染
   线程绑核心 2 —— 老机上崩溃是预期结果，换任何版本都没用。
1. **dspfirm.cdc** 已复位；更激进的对照是**直接删掉** SD 卡上这个文件。
2. **SD 卡 / 盘镜像**：必须 FAT32；`game.wbfs` 3,508,535,296 B、WBFS 头、
   ID `RMGE01`（已校验）。真机 WBFS 要实时 AES 解密，读取错误会 abort；
   换张卡或重拷一次排除坏块 / 传输损坏。
3. **Luma / 系统版本**：过老的 Luma 可能不认 New3DS 804MHz 配置；记下版本。
   CIA 能装说明 sig patch 大致可用，但 3dsx 走 HBL 是另一条路径。
4. **★ 唯一能真正定位的东西：`SD:/luma/dumps/` 的 ARM11 exception dump**
   （`arm11_exception_*.txt` / `.bin`）。里面有异常类型、PC/LR、进程名，
   能直接看出崩在 DSP 初始化、GPU 还是读盘。**没有它，PC 侧只能继续猜。**
   目录不存在就在 Luma 配置里确认 exception handlers 开启后复现一次；
   彩色异常屏拍照也行。

4. Luma 版本 + 系统版本；SD 卡是否 FAT32

第 1 项：你装的 CIA 是「未上过真机的优化版」——已修
----------------------------------------------------
之前给你的 `SMG-3DS.cia` 基于本项目编译的 **gpu-overlap 优化版**
（`docs/untested/gpu-overlap.diff`）。作者原话是这个补丁只在 Azahar 验证过，
**从未在 PICA200 真机上跑过**；它改了 `C3D_FrameSplit` / gxCmdQueueRun 的时序，
真机上完全可能触发 GPU 异常导致系统重启。这是当前首要嫌疑。

**现在 `cia/SMG-3DS.cia` 已换成官方 v0.1.0 原版 ELF 重打的 CIA**：
  - 源码逐行核对 = 官方原版，只加了 5 行 GCC 15 链接修复
    （把 `__ctru_heap_size` 的 extern "C" 提到全局作用域，不改任何游戏逻辑）
  - TitleID 不变 `000400000FF3FF00`，**TitleVersion 提到 0.0.1**，
    所以 FBI 可以直接覆盖安装，不用先卸载
  - SHA-256 48c45d9adfb91cd9f27477e4c0a5d1da7622e883688191b5969a52c6f972f2c7
  - 优化版保留为 `cia/SMG-3DS-gpu-overlap.cia`（原 v2，仅供对照，别再装它）

做法：把这个新 CIA 拷到 SD 卡 → FBI 再装一次（同 TitleID，会覆盖）→ 重启 → 打开。


第 2 项：资源与 DSP 固件（3dsx 也崩就查这里）
----------------------------------------------
- **`SD:/3ds/SMG-3DS/` 必须完整**：`game.wbfs`(3,508,535,296 B, RMGE01)、
  `settings.ini`、`nand/`，以及 `SD:/3ds/dspfirm.cdc`。CIA 不自带这些。
  程序用绝对路径读盘，读不到会 abort。
- **`dspfirm.cdc` 已复位**：包里默认现在是官方 105 B 占位文本；别台机器的
  合法 DSP1 固件已移到 `optional/`。详见本文件开头【最新结论】。
  对照实验：重新拷一次 SD 卡上的 `dspfirm.cdc`，或直接删掉它再启动。
  要声音再用本机 DSP1 导出真固件覆盖。
- SD 卡必须 FAT32、剩余空间充足；`game.wbfs` 单个 3.268 GiB 在 4 GiB 限制内。


第 3 项：CIA 的 exheader 权限（3dsx 正常才查这里）
---------------------------------------------------
当前 RSF 给的是 New3DS 满配：804MHz + L2 + Core2 + `SystemModeExt: 124MB`
+ `SpecialMemoryArrange: true` + DirectSdmc 读写。Azahar 全部接受，但真机
Luma/系统版本组合下，New3DS 内存重排（snake prod）可能与程序的线性堆假设冲突。
若第 1 项换原版 CIA 后仍崩、且 3dsx 正常，告诉我，我出一个**保守 exheader 版**
（关掉 SpecialMemoryArrange / 不强制 124MB）再试。
